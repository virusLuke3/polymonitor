# Panel 私有来源配置

所有 Panel 的密钥、来源入口和代理节点统一维护在项目私有 `.env`。公开来源也不在源码中保留真实默认地址。逐项检查见 [87 个 Panel 清单](panel-env-audit.md)，变量与消费者见 [来源绑定索引](panel-env-source-bindings.json)。

- Python：`runtime.environment` 统一加载，`data_sources.source_value("变量名")` 读取来源；`POLYMONITOR_ENV_FILE` 可显式指定私有文件，默认项目 `.env`。已注入的进程变量优先；显式空值不回退。密钥沿用现有环境变量名。
- JSON 目录：只保存 `${ENV_NAME}` 引用和频道／来源元数据，读取时由 `resolve_source_references()` 解析。API 不返回完整环境配置。
- 代理：`.env` 的 `POLYMONITOR_SOURCE_ROUTES_JSON` 保存主机到授权出口的有序列表，空字符串元素表示明确允许直连。来源级代理、SSH 目标、密钥路径和监听地址也来自私有环境配置；不使用脚本内的备用节点。
- 前端：浏览器直连的公开底图、雷达和证据链接使用 `VITE_PUBLIC_*`。Vite 仅注入这些公共变量及既有公开 API／地图参数，构建时拒绝带认证信息的公开 URL。密钥和代理不得使用 `VITE_*`。
- 部署：服务显式指定配置文件；需要服务专用环境时，由统一配置派生，保留声明过的覆盖顺序。重新加载对应进程后才算运行配置生效。不能只修改仓库文件就宣称线上已迁移。

`.env.example` 仅保留空值或占位符，不是可直接用于生产的来源目录；实际值只写 `.env`。新增来源必须同时更新示例、绑定索引、所属数据拥有者及必要的缺少配置测试。没有配置的来源不得暗中使用代码地址，也不得清空其他来源的成功数据。

源码中的协议 namespace、版权署名、解析字段和业务 ID 不是请求入口。上游返回的证据 URL、分页链接和临时媒体地址仍按原规则校验，不逐条写回 `.env`。测试使用独立公开 fixture 配置及模拟响应，不加载个人 `.env`。

本次保持采集周期、存储身份、Panel 布局与业务规则。配置迁移、测试通过、部署生效和上游连续健康必须分别验收。
