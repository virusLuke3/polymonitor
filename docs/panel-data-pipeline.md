# Panel 数据获取、存储与消费规范

本文是新增或升级 Panel 的必读开发规范，适用于已有数据的新视图、共享领域扩展和新来源接入。它规定数据链路的设计与验收；具体周期由 [分层刷新与采集周期](panel-data-cadence.md) 维护，资源身份由 [资源契约](panel-resource-contract.md) 维护，请求与恢复行为由 [公共生命周期](panel-runtime-lifecycle.md) 维护。Panel 注册与目录边界见 [Panel Modules](panel-modules.md)。

本地完整开发入口为 [Panel 开发统一指南](../document/开发/Panel开发统一指南.md)。`document/` 默认不受 Git 跟踪；干净 checkout 没有本地指南时，仍须执行上述 `docs/` 公共规范。本文是开发要求，不代表所有存量 Panel 已完成迁移或全部来源健康。

## 1. 先确定数据拥有者

沿用 WorldMonitor 按领域获取、共享结果、集中消费的思想，使用本项目现有实现：

```mermaid
flowchart LR
    A[已有数据拥有者或外部来源] --> B[领域采集、校验与计算]
    B --> C[正式数据与按需历史归档]
    B --> D[共享展示快照]
    C --> E[有预算的领域读取与 API]
    D --> E
    E --> F[公共 Runtime、解析与缓存]
    F --> G[一个或多个 Panel]
```

- 基础 Market、OrderFilled、Oracle、LOB 由 `market-data` 拥有。先查它已有的表、文件、只读接口与覆盖；新 Panel 不重复采集同一份基础数据。
- 新视图优先复用现有资源；新增字段先扩展所属领域；只有确实缺少生产者时才增加采集任务。Panel 数量不决定 worker、表或缓存的数量。
- API 优先读取已有数据和快照。已有按需补齐或后台恢复必须保留去重、锁、限流和总期限；页面 GET、用户数量或手动刷新不能触发无界采集。
- 本机读文件、远端 API 读库和浏览器读接口分别确认。写入方与读取方必须使用同一存储身份及兼容版本，不能只看同名表、key 或 HTTP 200。

## 2. 按用途选择存储

下表列出当前可复用入口和选择规则。公共展示快照统一使用 Redis；正式历史、私有状态和浏览器副本按各自用途保留。领域决定新鲜度和可展示年龄，不能自行建立第二个公共 seed 权威存储。

| 层次 | 本项目入口与用途 | 新 Panel 的要求 |
| --- | --- | --- |
| 正式数据与历史 | 数据拥有者管理的 PostgreSQL、ClickHouse、文件或领域专用存储 | 链接真实表／数据集与读取契约；需要回测或版本时单独确认历史能力 |
| 服务端展示快照 | [RedisSnapshotStore](../scripts/runtime/redis_snapshot_store.py) 的 Redis 当前快照；SQLite 只保留历史、私有状态和迁移前备份 | 记录写入者、namespace/key、schema、TTL、最大保留年龄和容量；复用所属领域的发布与恢复路径 |
| 首屏和批量读取 | [bootstrap](../scripts/api/services/bootstrap_service.py)、[runtime 批量路由](../scripts/api/routes/runtime_panels.py) | 用现有接口降低首屏请求；重组或重发不改变条目来源时间 |
| 浏览器会话 | [公共 Runtime](../webpage/src/panels/runtime-store.ts)、[参数化资源](../webpage/src/panels/usePanelResource.ts) | 同一完整 key 共享请求和状态；Panel 不再维护独立轮询或第二份业务缓存 |
| 浏览器持久缓存 | [resource-cache.ts](../webpage/src/panels/resource-cache.ts) 的显式公共数据缓存，IndexedDB 持久副本＋小资源 localStorage 热副本；地图另有专用资源契约 | 复用公共契约的版本、身份、原始年龄和容量校验；存储不可用不能破坏显示或布局偏好 |

WorldMonitor 的 Upstash Redis、R2／KV 和 IndexedDB 是其架构参考。**不能据此声称本项目所有 Panel 已接入这些服务，也不要求新增 Panel 自行创建这些存储。** 通用公共资源现在通过同一个 `resource-cache` 写入 IndexedDB；小资源另外保留有界 localStorage 同步副本。`cache: null` 的盘口／合约资源不落盘。容量、失效、降级和迁移见 [共享生命周期](panel-runtime-lifecycle.md#shared-persistence-capacity)。这一结论来自公共层实现和消费者验证，不能从地图拥有 IndexedDB 推导。

`panel_snapshots` 按 namespace/key 更新当前值，浏览器缓存用于展示恢复，都不能充当完整历史档案。需要历史时，明确原始记录、源版本、实际可用时间、保留范围和历史读取入口；事后下载的资料不能自动成为当时可用的策略输入。

缓存键包含影响响应的全部参数与适用版本，包括实体、市场、窗口、limit，以及实际存在的 as_of／revision。账户或权限相关结果按身份隔离，不自动进入公共缓存。过期或错版本缓存拒绝使用；清理只操作本缓存命名空间，不能清空用户布局或其他应用存储。

## 3. 获取、发布和读取各自有预算

### 浏览器恢复与服务端 seed 的边界

服务端命中 seed 只省去采集与计算，仍有浏览器排队、网络和 API 读取成本。所有公共概览数据拥有者必须声明并复用同一套持久缓存策略，纯视图沿用 owner 的 key；注册检查拒绝遗漏，实时执行资源显式声明只保留内存及原因：挂载时先校验并恢复已有快照，再按既有检查周期更新。恢复不得等待 bootstrap、可见性请求队列或远端 API；bootstrap 加载中也不能遮住已恢复的有效内容。首次访问、缓存缺失或超过领域保留期限时，才显示冷加载状态。

链路为“已有后台 owner → Redis 正式展示快照 → 只读 API → 共享 Runtime → 浏览器持久副本 → Panel”。seed 是预先采集生成的数据，不是样例数据。NBA、资讯等已有定时 owner 的公共读取应在缺失时快速报告 warming/unavailable，不在用户请求中同步重跑上游采集。已批准的按需补齐例外必须逐项声明预算与去重，不能扩大为通用回退。

本地副本保存完整资源身份、schema 和原始数据时间；最近成功检查时间与数据新鲜度分别维护。新鲜且尚未到浏览器检查时间时复用；到期但仍在保留期限内时保留内容、后台检查；失败保留旧值及明确异常；合法空结果可以清空。复制、恢复或失败都不推进来源时间。账户私有数据、执行报价及撤销敏感结果不得自动进入公共持久缓存。

WorldMonitor 的参考依据（本地核对版本 `65860c21bb1b9987915609792b9856bc9e67565e`）是 `scripts/seed-token-panels.mjs` → `server/worldmonitor/market/v1/list-defi-tokens.ts` → `src/services/market/index.ts`，浏览器恢复由 `src/utils/circuit-breaker.ts` 与 `src/services/persistent-cache.ts` 实现。其 bootstrap 在线时通常先联网、失败再恢复本地副本；本项目不复制这段首屏等待。默认加密行情只读 seed，自选币种缺口与新闻摘要可有界访问上游，不能描述为所有接口都是 seed-only。参考存储产品不作为本项目基础设施要求。

实现身份、容量、采用范围及验证入口见 [共享生命周期](panel-runtime-lifecycle.md#reload-recovery)。验收必须实际保存一次成功结果后刷新，在延迟/失败请求下证明旧内容先显示，并核对后续成功替换、原时间、正常空、到期淘汰、身份隔离和布局不变；生产截图使用真实 API。

采集器复用已有 HTTP 客户端及生命周期，明确连接和读取超时、整轮期限、并发、响应大小、来源配额、失败退避和退出清理。同一轮不重叠；慢来源在共享 worker 内独立计时。失败继续按原策略退避，不能让每个快周期反复调用失败的慢来源。

数据库按实际机器上的全部 API／worker 核对连接与查询预算，不能给每个 Panel 各设一份额度后相加超限。读取需有行数／字节／时间边界；有界等待计入同一个总期限，不能用无界排队或无限重试掩盖容量问题。依赖读取与外层缓存锁的边界、锁顺序必须明确，避免嵌套争锁和无关资源互相阻塞。市场读取参考 [Market panel reads](market-panel-reads.md)，其具体数字不自动套用到其他领域。

发布前校验身份、字段、单位、来源时间和覆盖，确认写入结果；旧任务不得覆盖新快照。各来源分别保留最后尝试、最后成功和错误，失败不重置成功时间。保留旧值必须保留原始时钟；合法空结果、错误、过期和未接入分别解释，不能用旧值伪装新值或用空列表伪装成功。

公共 seed 由统一 `create_snapshot_store` 工厂构造，生产默认 Redis。`publish_snapshot` 必须确认正式写入才能推进成功元数据、通知和游标；Redis 故障必须暴露，不切回 SQLite，也不读取旧 Redis 镜像。SQLite 模式只用于显式离线测试与人工回滚。当前生产切换和逐项验收记录见本节末尾，不能以代码已完成代替上线状态。

### Redis 公共快照契约

- 存储身份：`POLYMONITOR_SEED_REDIS_URL`（未配置时使用既有 `POLYDATA_REDIS_URL`）和 `POLYDATA_REDIS_PREFIX`，键版本 `seed:v1`；保留原 namespace/cache_key，转义各字段避免碰撞。`snapshot:*`、`runtime:*`、公共 `source:*`、`seed-meta:*` 和 AI 当前结果复用该入口；账户、配额、审计、AI 历史和加密历史仍属于原数据库。
- 四个独立时钟：来源时间在 payload 内原样保留；`updated_at` 为成功发布；`expires_at` 决定普通读取是否新鲜；Redis 物理保留默认为至少 7 天（原 TTL 更长则沿用）。7 天不代表数据可展示 7 天，领域原有最大年龄和浏览器保留规则继续执行。
- 写入单键原子替换；拒绝早于当前来源版本的发布。已有采集锁统一使用 Redis 租约，续租必须核对所有者，持锁写入必须在同一 Lua 操作内核对所有者。失败或过期所有者不得覆盖新值。
- 单条上限 16 MiB；namespace 默认上限 2048 条，已有更小 `max_entries` 优先；Redis 连接/读写各 1 秒，不自动重试。正式部署使用隔离的本机 Redis seed 实例：512 MiB、noeviction、AOF everysec、持久卷；不修改既有 Redis 队列实例。部署文件为 `deploy/redis/compose.yml`。
- 批量 API 对已声明的 namespace 使用 pipeline 预读，最多 128 键／32 MiB；领域函数仍按完整 key 和原始时钟校验。动态来源按需读取同一 Redis，并在单次批量请求内合并重复读，不建立派生快照。
- 迁移只读取原 SQLite，保留 payload、更新时间和过期时间；跳过已经超过物理保留的记录。原文件作为回滚备份保留，不作为在线回退源。API 缺失快速返回现有 warming/unavailable；动态参数的有界补齐沿用原领域契约。
- Redis 集中快照与浏览器 IndexedDB 是两层：前者供所有用户共享、采集器持续更新，后者使刷新页面优先恢复内容。当前盘口、选中合约和撤销敏感数据仍需现有实时校验。


网络出口属于运行配置，不是业务数据源。先核对运行主机、代理协议与客户端支持、有效环境变量及真实目标可达性；使用已授权出口，不自动切换用户代理或恢复已停用的服务、网关、隧道。既有授权无需重复询问；缺少必要路由选择时再明确请求。配置示例只写变量名与用途，凭据和私有部署位置留在运行环境。

### 3.1 密钥、数据源和代理统一由 `.env` 配置

**所有 Panel 及其共享数据拥有者执行以下两条硬性要求，公开、无密钥的数据源也不例外：**

1. **所有密钥和数据源入口保存在 `.env`，不得明写在脚本中。** API key、token、账号密码、签名凭据，以及 API/WS 基址、完整端点或 URL 模板、RSS/HLS/下载入口、远端数据服务地址等，都从 `.env` 读取。主源和备用源同样适用；不得用源码常量、默认参数或 `getenv(..., "真实地址")` 隐藏一个硬编码回退。
2. **所有代理节点及路由选择保存在 `.env`，不得明写在脚本中。** 包括代理协议、主机/IP、端口、认证信息、SSH 节点/用户/密钥文件路径，以及按来源选择的主备节点、顺序和直连策略。节点故障只能在 `.env` 明确声明且已授权的范围内处理，不能自动改主 Clash、继承未声明的系统代理或启用代码里的备用节点。

落实方式：

- 项目 `.env` 是实际值的统一维护入口；已有配置加载器在启动时读取并向客户端/领域服务注入配置，业务模块不各自扫描多个环境文件。部署通过 `EnvironmentFile` 或等效机制注入同一份配置；需要服务专用 `.env` 时，从统一配置派生并声明加载路径及覆盖顺序，不能维护另一套相互冲突的值。
- Python/TypeScript/Shell、provider/catalog、注册项、systemd、工作流及 JSON/YAML 均不得成为真实密钥、来源地址或代理节点的另一个维护位置。旧路由文件若保留兼容，只能由 `.env` 配置生成；文件路径来自环境变量，并不等于其内部节点已完成迁移。
- 代码保留来源标识、字段解析、业务规则、查询参数拼装和校验；按配置的端点/模板构造请求。上游返回的原文链接、分页游标或临时媒体地址是业务数据，仍需校验和归档，不把每条响应链接另写进 `.env`。文档中的公开来源引用也不充当运行时默认地址。
- 必需值缺失或格式错误时，该来源明确标为未配置/配置错误并停止其请求，其他已配置来源继续工作；可选密钥缺失只关闭对应授权能力。保留历史值遵循原时间与过期规则，不能伪造新成功，也不能回退到写死的来源或代理。
- `.env` 及含真实值的部署派生文件不提交 Git；`.env.example` 只列变量名、用途、必需性及空值/占位符。密钥、私有节点和完整认证 URL 不进入日志、截图、公共 API、缓存键或 `VITE_*` 前端包；公共展示需要的来源名称、证据链接由后端按字段输出，不能整体透传环境配置。

本节覆盖存量及后续开发。逐项配置检查见 [86 个 Panel 清单](panel-env-audit.md)，变量到使用文件的映射见 [来源变量索引](panel-env-source-bindings.json)。源码迁移和实际服务部署分别记录，不能据此推断上游健康。

实现入口：Python 使用 `runtime.environment` 与 `data_sources.source_value()`；JSON 目录以 `${ENV_NAME}` 引用。`POLYMONITOR_ENV_FILE` 指定私有文件，未指定时读取项目 `.env`；显式进程变量优先，空值不回退。`POLYMONITOR_SOURCE_ROUTES_JSON` 在 `.env` 中保存主机到已授权出口的路由表；旧 `SOURCE_ROUTES_FILE` 不再作为独立节点配置。浏览器必须直连的公开底图、雷达和公共证据链接使用 `VITE_PUBLIC_*`；构建器仅注入公开变量及既有公共 API／地图参数，不导出整个环境。协议 namespace、版权署名、解析规则和响应链接不作为固定取数地址迁移。

部署验收还须比较实际进程环境与个人 `.env`：旧 `EnvironmentFile`、systemd `Environment=` 和 drop-in 可能覆盖新配置。不能只验证 `POLYMONITOR_ENV_FILE` 路径存在。来源专用服务应删除过时覆盖，或用明确的 `UnsetEnvironment` 清除旧代理/来源变量后由统一加载器读取 `.env`；数据库、运行预算等无关配置不随之覆盖。检查仅输出变量名、是否一致和可达性，不输出值。无明确路由的来源使用显式直连；来源级主备路由、SSH 参数仍只从个人 `.env` 注入。

## 4. 四层周期单独声明

每个资源必须说明：来源发布／观察节奏、采集尝试周期、浏览器检查周期、缓存新鲜阈值与最大保留时间。具体值及低延迟例外遵循 [周期规范](panel-data-cadence.md)，不在本文复制第二张周期表。

概览按分钟、发布型统计跟随来源节奏；盘口、订单流、指定价格源的低延迟需有业务依据。历史／静态资源不制造自动更新。快照重新封装、缓存复制或浏览器恢复不能改写来源时间；新请求成功不代表新业务数据产生。

这些声明属于开发契约和诊断信息，不要求在正文展示 `Check … · Source …`、通用 `PARTIAL` 或多行内部时钟。业务上必要的原始时间和具体缺失按既有 Panel 展示规范呈现。

- [ ] 所有密钥、数据源入口及代理节点由 `.env` 注入；核对脚本、catalog、默认参数、主备回退和部署配置，无真实值硬编码。仅移动到另一份 JSON/YAML 不算完成。
- [ ] 实现时验证更改 `.env` 后的实际目标/出口、缺失配置时的行为与覆盖顺序；诊断只输出变量名、来源标识和脱敏结果，真实配置未进入 Git 或前端产物。
- [ ] 写入和读取的真实存储身份一致，字段、单位、覆盖与源时间通过校验；验证到目标 API 和 Panel 消费者。
- [ ] 短周期观察至少两次自动到期执行，证明成功获取及发布；不要求值必须变化。长周期使用配置、调度测试及已存在的成功记录，注明尚未观察的完整周期。
- [ ] 请求去重、参数隔离、取消与超时按本次风险验证；一个消费者退出不取消其他消费者需要的资源。
- [ ] 适用的来源失败、合法空、过期、存储恢复和恢复后重新成功有证据；原始时间没有被续期。
- [ ] 有历史需求时验证版本、范围和缺口；当前快照或趋势图不代替历史验收。
- [ ] 新旧部署依赖与资源预算核对完成，没有误拉起已退休服务。代码、本地测试、部署身份、实际数据和生产验收分别报告。

纯文档任务只检查规范、链接与一致性；实现任务按受影响范围运行必要检查；生产 UI 验收遵循当前任务授权及仓库发布要求。不得只凭进程 active、接口 200 或非空结果宣称整条链路完成。

## Finance 外源纯投影

`tradfi-perp-radar`、`crypto-etf-flow` 和旧 Finance `stablecoin-monitor` 接口直接读取既有外源 owner 的 `runtime:finance:external-sources / v1` Redis 快照，再做有界纯转换。GET 不发上游请求、不写派生快照、不依赖 Finance watcher 下一轮转换，外源 owner 仍按原 900 秒周期获取并发布。已有 Finance 兼容快照不新增发布者或缓存层。

该外源 owner 的 CFTC 分支也复用明确配置的 `SourceSession` 路由；连接恢复不改变官方每周报告日期。正式读取与入库时间、报告期分别验证，不能把重新获取旧报告称为新报告发布。

Broker Research 继续由 Finance watch owner 采集并写入 `runtime:finance:broker-research-watch / v1`，API 只读、浏览器复用原 Runtime。Edison 配置应指向官网公开研报列表，而不是研究业务介绍页；当前列表身份存于私有配置。报告标题未含股票代码时，只读取报告表格中明确的 `Code` 字段，不从正文任意大写词猜测。公司名、报告发布时间和原文链接保留；缺少目标价不补造目标价。每个来源仍最多 10 篇候选，列表 16 秒、单详情 12 秒，沿用原刷新、缓存与共享资源预算。来源没有可解析代码或仅提供客户端页面时保持 empty/no-links/partial，不能仅因列表 HTTP 200 标为采集成功。当前验收另见当次数据可靠性记录。

部署统一来源配置时必须包含 `polymonitor-external-panels@` 的定时采集任务，不能只更新常驻 watcher。现有启动器调用 `load_environment()`；部署 override 设置 `POLYMONITOR_ENV_FILE` 指向该部署的私有主配置，并用 `UnsetEnvironment=POLYDATA_DISABLE_DOTENV POLYMONITOR_SOURCE_ROUTES_JSON POLYMONITOR_SOURCE_ROUTES_FILE` 去掉旧 EnvironmentFile 的传输覆盖。其他端点、凭据、存储位置和资源预算保留。仅修改磁盘 `.env` 不会覆盖已经存在的进程变量；必须检查下一次正式进程的配置与成功采集时间。已有活跃一次性任务允许完成，下一轮按各来源 due 时间读取，禁止清除限流冷却或强制全量重采。 Cleveland Fed Nowcast 的公开 HTML 也走既有 SourceSession 来源路由；路线配置属于正式采集进程，不能只验证命令行探针。来源报告的 Updated 日期与本次成功采集时间继续分开保留。

组合 `generatedAt` 和每行 `fetchedAt` 保持原始来源时间；沿用 15 分钟新鲜阈值及 30 分钟最大保留时间，单行先按自己的时钟过期，缺失或无效组合时钟不能改用读取时间。浏览器检查周期、字段单位、来源退避和网络预算不变；每次读取仅查询既有有界快照，最多返回 36 行。针对测试验证最新源立即可见、禁止 HTTP/写入、保留行时钟及过期边界；部署后仍需核对正式 API 的源时钟与 Redis，不能用单元测试代替运行验收。

这里的旧 Finance Stablecoin 接口只投影外源供应/价格数据；当前前端 `stablecoin-monitor` 使用 [Crypto Strategy owner](crypto-strategy-panels.md)，不属于此次接口修复。

## 新来源目录与首批公告面板

候选目录仅是调研输入，不能推定接口已验证、已有授权或数据齐全。每个字段先说明来源、实体、单位、发布与采集时间、覆盖和缺失含义；预测与官方事实分开。失败保留实体级最后成功数据和原始时间，有限重试不瓜分过短预算。公共 GET 不触发上游请求。公司财报与公告、政策进程的实际来源、存储、周期、视觉差异和验收见 [功能契约](official-disclosures-panels.md)。
