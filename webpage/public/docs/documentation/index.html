Getting Started

Introduction

polyData Monitor is an open-source, real-time Polymarket intelligence dashboard that aggregates market prices, on-chain flow, oracle activity, order-book depth, macro context, news, and AI-powered analysis into a single map-first interface.

The product is designed for traders, researchers, operators, and builders who need to understand what is moving, why it is moving, and where resolution or liquidity risk is building.

What you can do

  • Track active Polymarket markets and fast-changing outcomes in real time.
  • Inspect market depth, recent trades, whale flow, suspicious activity, and oracle history.
  • Connect market movement with related news, reports, video, research, macro data, sports, weather, and crypto signals.
  • Run the dashboard as static assets behind Nginx while `/wm-api/` proxies to the runtime API.
Quickstart Build the Vite/Preact dashboard and run the local API helper. Architecture Review data pipelines, API boundaries, runtime cache, and frontend serving. Panel Modules Add panels through frontend and backend manifests instead of dashboard shell code. Deployment Use public Nginx and systemd templates for production-style hosting.

Design Philosophy

polyData keeps dense operational information visible without turning the dashboard into a text wall. Panels use stable scan paths: entity on the left, title and metadata in the center, value or status on the right.

Platform Overview

The workspace combines a Flask API, PostgreSQL-backed market data, Redis and SQLite runtime snapshots, and a Vite/Preact frontend. Production hosting serves built frontend files from `/var/www/polydata` and proxies API calls through `/wm-api/`.

Features & Interface

Core surfaces include active markets, grouped outcomes, order-book snapshots, OrderFilled flow, oracle events, related intelligence, AI market briefs, macro panels, sports odds, weather markets, and Telegram publishing workflows.

Panel Modules

New dashboard panels should live in their own modules with explicit metadata, fetch behavior, rendering, and optional runtime snapshot routes. The central registry should only aggregate modules.

Deployment

For production-style hosting, build the frontend locally or on the serving host, publish `webpage/dist` into the static web root, and keep API process management in systemd.

Authentication

The current public dashboard does not require end-user authentication. Runtime API deployments should keep private tokens, upstream keys, and host-specific details outside public docs.

Runtime API

The frontend reads through `/wm-api/`, which lets Nginx route the browser to the active API service without hard-coding private hosts in client code.

Errors

Panels should show cached, stale, empty, or degraded states clearly. Operators can verify service health through the public deployment templates and the runtime health endpoints.

Signal Intelligence

The signal layer connects price action with chain flow, liquidity, external content, and generated market context so a move can be reviewed from one surface.

Oracle Watch

Oracle panels track proposal, settlement, and resolution context so markets with nearby UMA or settlement risk are easier to spot.

Research Links
