Polymarket Concepts

Oracle

Oracle data explains how a market leaves the trading phase and becomes a settled outcome. For polyData, oracle indexing is not a side feed; it is part of the market lifecycle.

What the oracle decides

A Polymarket price can move toward 0 or 1 before a market is final, but price alone does not prove settlement. The oracle layer records the resolution process: what answer was requested, what was proposed, whether the proposal was disputed, and what finally settled. This is the difference between market consensus and settlement state.

That distinction matters near resolution. Two markets can both trade near 99%, but one can be final while another is still waiting for a proposal, entering a dispute window, or carrying wording risk. polyData's oracle panels are designed to make those states visible.

UMA event flow

Many Polymarket markets resolve through UMA-related adapter and oracle contracts. The lifecycle can include question initialization, price request, price proposal, dispute, and settlement. polyData stores transaction hashes, log indexes, block numbers, event times, proposed prices, settled prices, participants, and matching metadata for these events.

Market resolution path:
1. Question is initialized or prepared through an adapter
2. Oracle price is requested
3. A result is proposed
4. The proposal can be disputed
5. The oracle settles the final answer
6. The market becomes final and redeemable

Identity matching

The hard part is not only reading logs. The hard part is mapping oracle logs back to the correct market. Some events can be matched directly through question id or condition id. Others require adapter mappings, ancillary data decoding, title/date matching, or neg-risk request mappings. polyData preserves those matching paths so an analyst can audit why an oracle event belongs to a market.

This is also why the market catalog stores more than display names. Gamma ids, slugs, condition ids, question ids, oracle addresses, event metadata, token ids, and raw timing fields are all useful when a settlement event has to be reconciled with a market page.

How polyData uses oracle data

The Oracle Feed panel surfaces recent oracle events across markets. Focused market views show whether the selected market is still trading, awaiting oracle activity, proposed, disputed, settled, or final. AI and flow panels can then separate price momentum from resolution risk.

In the broader lifecycle, oracle indexing closes the loop from discovery to archive. A market is discovered, becomes tradeable, accumulates price and OrderFilled history, approaches close, enters oracle review, settles, and remains queryable as historical evidence. Without the oracle layer, historical market data would show where prices ended but not why the market became final.
