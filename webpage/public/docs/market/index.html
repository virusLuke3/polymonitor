Polymarket Concepts

Market

Polymarket has several objects that sound similar but live at different layers: market, event, series, slug, and token. polyData keeps them separate because pricing, liquidity, ownership, settlement, and user navigation do not happen at the same level.

Market, event, series

A market is the smallest tradable question. In the common binary case, it asks one concrete Yes/No question and has two outcome tokens. An event is a higher-level container that groups one or more related markets. A series is a broader collection that can organize events across a season, tournament, recurring topic, election cycle, or long-running theme.

For example, a presidential-election series can contain one event for the election winner. That event can contain separate Yes/No markets for individual candidates. The frontend often shows the event page, but the order book, tokens, prices, fills, and settlement data belong to the individual markets underneath it.

Slug and token

A slug is not the market itself and it is not a token. It is a human-readable lookup key used in URLs, API routes, and audits. It is useful for linking a browser page to a known object, but it is not a chain identifier and it is not the asset a wallet holds.

The token is the lowest-level settlement asset. A binary Polymarket market has a Yes token and a No token. These outcome tokens are ERC-1155 assets on Polygon built around the Conditional Token Framework. If the event happens, the Yes token redeems to $1 and the No token redeems to $0; if it does not happen, the reverse is true.

Price history

Polymarket price history should not be read as traditional OHLCV candle data. The public historical series is price history, not a full open-high-low-close-volume tape. For supported markets it can be requested at fine intervals such as one minute, but the value is tied to the platform's displayed probability surface rather than an exchange-style OHLCV bar.

The key price concept is midpoint: the average of the current best bid and best ask. Polymarket's frontend generally displays midpoint. When the bid-ask spread is wider than $0.10, the frontend falls back to the last traded price. polyData models this distinction explicitly so charts, BBO panels, and trade panels do not pretend they are reading the same data layer.

LOB data

Polymarket supports live order book data, but it does not provide a complete official historical limit-order-book archive. That means historical analysis has to distinguish between price history, live BBO snapshots, depth snapshots captured by polyData, and actual trade or fill records. A price move without historical LOB depth cannot always prove where liquidity sat before the move.

polyData therefore stores market identity, token identity, price history, BBO/depth state, and on-chain fills as separate layers. This lets an analyst ask whether a market moved because the midpoint changed, the spread widened, the book was thin, a large taker consumed resting orders, or the market entered a resolution phase.
