Collection paths

polyData uses several independent collection paths because no single Polymarket endpoint is complete enough for historical and live analysis. Gamma provides the canonical event and market surface; CLOB provides condition-level market and token data; Polygon RPC provides registry, trade, and oracle truth.

Cache layers

ClickHouse stores high-volume OrderFilled and cashflow data; PostgreSQL stores canonical market, oracle, serving, and status tables; Redis and SQLite snapshots protect the UI from slow or stale upstream calls.

Sync loop

The sync loop refreshes markets first, then scans oracle and trade blocks with overlap windows. This ordering matters because markets can arrive after chain activity; re-scanning recent blocks lets late-discovered markets attach to already-seen trades and oracle events.
