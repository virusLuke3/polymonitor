Polymarket Agent

The Polymarket Agent is polyData's market-wide forecasting analyst. It turns active markets, fill tape, oracle events, related-market structure, news, and historical forecast memory into auditable AI panels for the dashboard.

What It Produces

The agent powers the three market-wide AI panels on the dashboard. They share the same architecture and seed payload, but use different lenses so each panel emphasizes a different analyst job.

Panel Lens Primary use
AI Insights
overview		 Market-wide brief Find the most important live market read, the strongest probability structure, and the main caveat.
Special Radar
special		 Unusual-market radar Highlight special situations such as 50c repricing zones, conflicting prices, deadline ladders, or stale/resolution risk.
Trend Watch
trend		 Trend and catalyst synthesis Connect active markets to broader narrative clusters, related-market spreads, catalysts, and next watch items.

Architecture

The runtime is a LangGraph supervisor-worker state graph. Deterministic nodes create compact evidence and quantitative structure first. Specialist workers then reason over that state, and the panel writer converts it into dashboard JSON.

Layer Node Responsibility
Supervisor langgraph-supervisor-stategraph Schedules the node graph, preserves shared state, records events, and routes the run to the final writer.
Evidence evidence_builder Compresses source metrics, top market, category concentration, and input hashes into a deterministic evidence packet.
Structure related_markets Builds deadline ladders, related-market spreads, probability-sum warnings, and arbitrage-style stress scores.
Quant quant_forecaster Computes top flow markets, repricing zones, price drift, volatility, LOB spread, fill-tape microstructure, and price-source conflicts.
Workers microstructure, catalyst, resolution Separate agents inspect trading structure, external catalysts, and resolution/oracle risk with ReAct-style tool observations.
Discipline calibration_agent, skeptic Discounts weak evidence, challenges generic claims, and forces the output to stay anchored to named markets and probabilities.
Memory reflexion_memory Stores reusable lessons such as price-drift episodes, related-market stress, and fill-tape conflict observations.
Writer panel_writer Produces the final panel schema: brief, focus, specialMarkets, themes, watchlist, evidence, and graph metadata.

Runtime Flow

  1. The GCP timer or manual seed command creates one shared forecastRunId for the configured lenses.
  2. The seed payload loads active markets, market groups, recent trades, oracle events, content, cached signal feeds, and forecast memory.
  3. The low-cost fill-tape enrichment reads recent flow for the top markets so the agent can distinguish live prices from stale detail rows.
  4. The LangGraph supervisor runs deterministic evidence, related-market, quant, and memory nodes before invoking specialist workers.
  5. Workers use compact ReAct tool traces such as quant_snapshot, data_quality, catalyst_scan, and resolution_scan.
  6. The calibration and skeptic nodes apply data-quality discounts and force probability discipline.
  7. The panel writer returns compact dashboard JSON, which is stored in the snapshot cache and exposed through the runtime API.

Inputs

Input Where it comes from Why it matters
markets Active market snapshot Provides title, category, latest price, 24h volume, trade count, end date, and candidate universe.
marketGroups Market group snapshot Allows the agent to inspect outcome ladders, deadline curves, and probability-sum anomalies.
topMarketFillTape Recent flow for top markets Gives fresh fill prices, VWAP, fill drift, paired-fill ratio, and price-source conflict detection without full LOB costs.
trades and oracle Recent trade and oracle snapshots Help separate normal trading flow from resolution-adjacent or already-settled behavior.
content and signals News, alpha, whale, and suspicious-flow caches Connects market moves to catalysts while keeping claims grounded in available evidence.
forecastMemory Snapshot store Feeds prior lessons, Brier score fields, and episodic memory back into the next run.

Outputs

The primary output is a panel snapshot. The same run also stores quantitative diagnostics and node-level audit events so a bad or surprising panel can be traced back to the exact node and evidence packet.

Quality Controls

  • Price-source conflict detection: compares snapshot price, market detail price, latest fill, fill VWAP, and detail yes/no price before trusting a probability read.
  • Data-quality discounts: labels missing change24h, missing LOB spread, stale fill tape, and group-volume/trade-count mismatch.
  • Event log: records run_id, node, input hash, output JSON, model, token usage, latency, errors, and evidence references.
  • Prompt caps: compact context keeps writer calls below model input limits while preserving high-signal quant evidence.
  • Fallback safety: if the gateway, model, or budget path fails, deterministic fallback snapshots keep the dashboard available but expose status and error state.

Runtime APIs

Endpoint Returns
/runtime/agent/market-wide-insights/<lens> The dashboard-ready panel snapshot for overview, special, or trend.
/runtime/agent/market-wide-quant/<lens> The latest quant snapshot, including fill-tape microstructure and price-source conflicts.
/runtime/agent/market-wide-events/<run_id> Node-level event log for audit, debugging, latency inspection, and model-output review.
