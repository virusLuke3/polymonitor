Polymarket Agent

The Polymarket Agent is not a room full of LLM personas chatting with each other. It is a structured forecasting workflow: deterministic evidence first, a small number of specialist agents second, limited debate and critique third, then calibration, panel adaptation, snapshot storage, and resolution memory.

Core Judgment

Prediction-market intelligence should optimize for evidence quality, calibration, and post-resolution learning. More agents only help when they own different evidence surfaces or decision checks. A 20-persona or 50-persona swarm would add cost and drift without making the final probability more auditable.

  • Structured state beats long conversation. Every node writes compact JSON with input hashes, evidence references, model usage, latency, and errors.
  • Specialists must be evidence-bounded. Resolution, microstructure, catalyst, related-market, and quant nodes should not invent data outside their input packet.
  • Debate should be small and explicit. Bull and bear agents run only after evidence exists, and their job is to stress one probability read rather than chat freely.
  • Calibration is a first-class output. The system should compare market-implied probability, agent probability, historical Brier score, category calibration, and data quality.
  • Resolution closes the loop. Polymarket markets eventually resolve, so every forecast can become memory: what evidence worked, what was stale, and what fooled the system.

Target Workflow

Market Trigger
  -> Evidence Builder
  -> Parallel Specialist Agents
  -> Debate / Critique
  -> Calibration Aggregator
  -> Panel Adapter
  -> Snapshot Store
  -> Resolution Memory

This graph is intentionally closer to an investment research workflow than to a generic role-play framework. It borrows the useful parts of financial multi-agent systems: analyst specialization, bull/bear review, risk control, structured reports, and reinforcement from realized outcomes.

Agent Roles

Node Type Responsibility
Supervisor State machine Routes the graph, enforces budget, retries failed nodes, records events, and never writes the forecast conclusion itself.
Evidence Builder Deterministic code Loads Polymarket prices, liquidity, volume, order book snapshots, trades, related markets, oracle text, resolution criteria, news, and search context.
Resolution Agent LLM specialist Parses market wording, title traps, resolution criteria, official-source hierarchy, oracle state, and ambiguous settlement paths.
Microstructure Agent LLM specialist Reads spread, fill tape, whale flow, paired YES/NO fills, price-source conflicts, liquidity gaps, and fake momentum risk.
Catalyst Agent LLM specialist Finds official news, event timing, external data releases, social or media catalysts, and only returns claims with evidence references.
Related Markets Agent Hybrid Links sibling markets, deadline ladders, same-event derivatives, category clusters, and adjacent-event price inconsistencies.
Quant Forecaster Non-LLM Computes price drift, volatility, spread, fill concentration, LOB metrics, historical-similarity features, and data-quality flags.
Bull Agent Debate node Argues why the probability should move higher using only the evidence packet and specialist reports.
Bear Agent Debate node Argues why the probability should move lower or why the apparent signal is stale, illiquid, or resolution-contaminated.
Skeptic Agent Critique node Finds hallucination risk, old news, low-liquidity traps, contradictory prices, and unsupported causal claims.
Calibration Agent Aggregator Combines market-implied probability, agent probability, Brier history, category calibration, and data-quality discounts into final confidence.
Panel Writer Adapter Does not re-reason from scratch. It converts the calibrated run into AI Insights, Special Radar, and Trend Watch views.

Three Panels, One Run

The three dashboard panels should not be three isolated agents. They should share one forecast_run_id, one evidence bundle, one event log, and one calibration state. The panels are lenses over the same run.

Panel Lens What it should emphasize
AI Insights overview Market-wide read, dominant probability structure, highest-value caveat, and why the board matters now.
Special Radar special Anomalous markets, low-liquidity moves, stale or conflicting prices, deadline ladders, and cross-market mispricing.
Trend Watch trend Category rotation, attention migration, catalyst clusters, and whether isolated event interest is becoming a broader trend.

Structured Inputs

The agent's job is to transform data into a calibrated market read. It should not compensate for missing data by writing more prose.

Input surface Examples Used by
Price and liquidity latestPrice, price24hAgo, volume, trade count, bid/ask, LOB spread Evidence Builder, Microstructure, Quant Forecaster, Calibration
Fill tape topMarketFillTape, fill VWAP, recent fill drift, paired-fill ratio, price-source conflicts Microstructure, Quant Forecaster, Skeptic
Resolution context Market title, rules, end date, oracle events, official source hierarchy, settlement state Resolution Agent, Bear Agent, Skeptic
External catalysts News, official releases, match feeds, government calendars, social/media trend signals Catalyst Agent, Bull Agent, Panel Writer
Related markets Same-event children, handicap markets, deadline ladders, adjacent category markets Related Markets Agent, Quant Forecaster, Calibration
Historical memory Prior forecast episodes, realized resolution, price drift after prediction, Brier score, category reliability Calibration Agent, Resolution Memory

Structured Outputs

Each node writes a bounded JSON object. The final panel is only one product of the run; the audit trail and calibration record are equally important.

{
  "runId": "fig-...",
  "marketId": "1843143",
  "node": "quant_forecaster",
  "inputHash": "...",
  "outputJson": {
    "priceDriftLeaders": [],
    "fillTapeMicrostructure": [],

    "dataWarnings": []
  },
  "model": "deterministic",
  "tokens": 0,
  "latencyMs": 12,
  "error": null,
  "evidenceRefs": []
}

Evaluation Loop

The architecture is judged by whether it improves forecasting discipline, not by whether the output sounds polished. The core metrics are calibration, discriminative power, and cost-quality.

  • Calibration: compare forecast probabilities against eventual resolution and compute Brier score by category and market type.
  • Discriminative power: measure whether high-confidence signals separate from low-confidence signals after resolution or price drift.
  • Cost-quality: compare token spend and latency against improvement in calibrated output and analyst usefulness.
  • Resolution memory: store why the system was right or wrong, then feed that lesson into the next run.
  • Replay audit: reconstruct a run from event logs instead of relying on a long conversation transcript.

Current State

The production system already follows part of this design. It uses LangGraph, shared lenses, deterministic evidence and quant nodes, specialist workers, calibration, skeptic checks, snapshot storage, and event logs. The next upgrades are narrower and more important than adding more personas.

Implemented Next iteration
Shared forecastRunId across overview, special, and trend lenses. Add explicit Bull/Bear debate over selected high-value markets only.
LangGraph supervisor runtime with event logging and ReAct-style tool traces. Promote event logs into the primary replay and benchmark surface.
Quant forecaster with fill tape, price drift, volatility, LOB spread, related-market scores, and price-source conflicts. Add market state classifier: live-active, stale-summary, likely-resolved, repricing-zone, derivative, placeholder.
Calibration agent and skeptic node. Back them with category-level Brier history and realized resolution memory.
Panel writer emits AI Insights, Special Radar, and Trend Watch. Make the writer a pure adapter over calibrated run state, not a second reasoning pass.

Design References

This design is closer to specialized forecasting and financial-agent systems than to generic role-prompt frameworks.

  • TradingAgents: financial workflow with analysts, bull/bear researchers, trader synthesis, risk review, and final decision control.
  • TradingAgents system architecture: structured reports and institutional-style coordination.
  • FinCon: manager-analyst hierarchy, risk control, and verbal reinforcement for financial decision workflows.
  • PROPHET: prediction-market modeling with price time series, event text semantics, and order-book microstructure.
  • ForesightFlow: coordination layer, calibration, discriminative power, and cost-quality evaluation for forecasting agents.
  • MASAI, SciAgents, and DrugAgent: task-specific systems that use short trajectories, explicit responsibilities, structured inputs and outputs, and domain knowledge instead of open-ended chat.
